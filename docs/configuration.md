# Конфигурация Elira

Конфигурация — один TOML-файл, по умолчанию `elira.toml`. Путь задаётся флагом
`--config` у команд `run` и `check`:

```
elira run --config /etc/elira/elira.toml
elira check --config /etc/elira/elira.toml
```

`check` только читает файл, проверяет типы и валидацию и печатает число маршрутов
и upstream'ов; сокеты он не открывает.

`migrate` конвертирует подмножество nginx-конфига в TOML:

```
elira migrate /etc/nginx/nginx.conf > elira.toml
elira migrate --output elira.toml nginx.conf
```

Поддержаны `upstream` с `server` и `least_conn`, `server`/`listen`/`server_name`,
`location` с `proxy_pass`, `root` + `index`, `return`, `try_files`, `add_header`,
`auth_basic_user_file`, `allow`/`deny`, `client_max_body_size`, `gzip`,
`ssl_certificate`/`ssl_certificate_key`, `access_log` и регулярные `location`.
`if`, `rewrite`, переменные и вложенные `location` не переносятся, а печатаются
предупреждением в stderr; вход не теряется, но результат надо прочитать
глазами. Несколько `server` в одном файле дают предупреждение: у Elira один
`listen`.

Конфиг можно разбить на файлы:

```toml
include = ["/etc/elira/conf.d/*.toml"]
```

`include` — строка или массив; поддерживается один `*` в имени файла.
Пути относительны каталога включающего файла. `[[routes]]` и `[[upstreams]]`
дописываются, таблицы сливаются по ключам, скаляры из include перекрывают
родительские. Вложенность ограничена 16 уровнями.

В значениях подставляется окружение: `${VAR}` и `${VAR:-default}`. `$$`
означает литеральный `$`. Неизвестная переменная без default — ошибка
загрузки, а не пустая строка.

Все структуры объявлены с `deny_unknown_fields`: неизвестное поле — ошибка разбора,
а не молча проигнорированная опечатка. `max_connection` вместо
`max_connections` не даст серверу стартовать, и это сделано намеренно. Ошибка
разбора печатается с путём к файлу.

Перезагрузка — `SIGHUP`: сервер заново читает файл, собирает новое состояние и
подменяет его атомарно. Если новый файл не проходит разбор или валидацию, в лог
пишется ошибка, а старый конфиг продолжает работать. Что применяется сразу, а что
требует рестарта, разобрано в разделе «Ограничения и поведение».

`listen_unix` поднимает второй слушатель на файловом сокете. PROXY protocol и
`sendfile` на нём не применяются; peer для логов и ACL — `127.0.0.1`. С
`unix_tls = true` тот же сокет терминирует TLS настройками `[tls]`, включая
SNI-сертификаты, mTLS, OCSP и ALPN `h2`/`http/1.1`; сертификат перечитывается
по `SIGHUP` для новых соединений. Без `[tls]` комбинация отклоняется.
`listen_unix_mode` выставляет права после bind (например, `0o660`), а
`listen_unix_owner` — числового владельца `"uid:gid"`; для чужого uid нужен
root. Сокет не удаляется при старте: существующий файл означает ошибку, а не
молчаливую замену чужого сокета.

## Дополнительные листенеры и процесс

```toml
listen = "0.0.0.0:8080"

[[listeners]]
listen = "0.0.0.0:8081"
name = "public"
tls = false

[[listeners]]
listen = "0.0.0.0:8443"
name = "secure"
tls = true   # использует общий [tls] или [acme]
```

Основной `listen` привязывается всегда; `[[listeners]]` добавляет адреса.
`name` задаёт имя для `routes.listeners`; без него используется
`listener-N`. Специальные имена: `default` (основной листенер), `unix` и
`http3`. Маршрут без `listeners` действует на всех листенерах; маршрут со
списком — только на перечисленных. Дубликаты имён и неизвестные имена
отклоняются. `tls = true` требует `[tls]` или `[acme]`; без него листенер
принимает открытый HTTP. Дубликаты адресов отклоняются. В worker-режиме
каждый воркер привязывает все адреса через `SO_REUSEPORT`; изменение списка
требует рестарта.

- `user` принимает имя пользователя или `uid:gid`. Смена происходит после
  bind всех сокетов и загрузки сертификатов, перед первым accept. Для смены
  нужен root; без него разрешён только совпадающий uid/gid.
- `worker_rlimit_nofile` поднимает soft и hard лимит `RLIMIT_NOFILE`.
- `worker_cpu_affinity` — список CPU; воркер с индексом N берёт
  `cpus[N % len]`, single-process — первый.
- `chroot` вызывается после чтения конфига и записи pid, но до `Runtime::build`
  и bind. Все пути в конфиге — сертификаты, логи, кэш, статика, config для
  reload, hook'и — должны существовать внутри нового корня. Супервизор
  остаётся снаружи, воркеры входят в jail.
- `pid_file` пишется супервизором или single-process процессом и удаляется при
  выходе.

Адреса везде имеют вид `IP:порт` (тип `SocketAddr` в TOML-строке), поэтому
`localhost:8080` не подходит — нужен `127.0.0.1:8080` или `[::1]:8080`.
Исключение — `servers` у upstream'ов и `allow` у `connect`: там допустимы
имена хостов.

## Верхний уровень

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `listen` | `IP:порт` | нет, обязательно | TCP-адрес основного HTTP-листенера |
| `listen_unix` | путь | нет | дополнительный HTTP/1.1 на unix-сокете |
| `unix_tls` | bool | `false` | завершать TLS на `listen_unix` настройками `[tls]` |
| `listen_unix_mode` | целое | права из umask | биты доступа к сокету, например `0o660` |
| `listen_unix_owner` | строка | нет | владелец сокета `"uid:gid"` |
| `h2c` | bool | `false` | HTTP/2 prior knowledge без TLS |
| `listeners` | массив таблиц | `[]` | дополнительные TCP-листенеры |
| `streams` | массив таблиц | `[]` | L4 TCP/UDP-прокси |
| `rewrites` | массив таблиц | `[]` | переписывание пути до выбора маршрута |
| `maps` | массив таблиц | `[]` | именованные переменные из таблицы значений |
| `geos` | массив таблиц | `[]` | переменные по IP/CIDR клиента |
| `splits` | массив таблиц | `[]` | переменные по процентному распределению |
| `user` | строка | нет | сбросить привилегии на пользователя после bind |
| `worker_rlimit_nofile` | целое > 0 | нет | поднять `RLIMIT_NOFILE` |
| `worker_cpu_affinity` | массив CPU | нет | привязать воркеры к CPU по кругу |
| `chroot` | путь | нет | войти в jail до загрузки runtime-файлов |
| `pid_file` | путь | нет | записать PID супервизора или single-process |
| `workers` | `1..64` или `"auto"` | `1` | процессы-воркеры с SO_REUSEPORT; нужен `reuse_port = true` |
| `proxy_protocol` | bool | `false` | ждать PROXY protocol (v1/v2) на каждом соединении |
| `reuse_port` | bool | `false` | SO_REUSEPORT; нужен для hot restart по SIGUSR2 |
| `sendfile` | bool | `true` | zero-copy статика на Linux через `sendfile(2)` |
| `sendfile_min_bytes` | целое ≥ 0 | `65536` | файлы меньше этого размера идут обычным путём |
| `server_header` | bool | `true` | отдавать `Server: elira` и сохранять заголовок upstream |
| `limits` | таблица | значения по умолчанию | лимиты соединений и заголовков |
| `tls` | таблица | нет (HTTP без TLS) | сертификат для TCP-листенера |
| `acme` | таблица | нет | Let's Encrypt через TLS-ALPN-01; вместо `[tls]` |
| `http3` | таблица | нет (HTTP/3 выключен) | отдельный QUIC-листенер |
| `log` | таблица | `text` | формат access-лога |
| `health` | таблица | выключено | активные проверки upstream'ов |
| `connect` | таблица | выключено | туннели `CONNECT` |
| `metrics` | таблица | нет (метрики выключены) | отдельный листенер Prometheus |
| `cache` | таблица | выключено | in-memory кэш ответов |
| `upstream_tls` | таблица | проверять системные корни | настройки TLS до upstream'ов |
| `error_pages` | массив строк | `[]` | глобальные страницы ошибок `"404 /404.html"` |
| `error_root` | путь | нет | каталог для глобальных `error_pages` |
| `upstreams` | массив таблиц | пусто | группы бэкендов |
| `routes` | массив таблиц | обязательно, не пусто | таблица маршрутизации по Host |

`routes` — единственное обязательное поле помимо `listen`. Пустой массив
отклоняется с ошибкой `no routes configured`.

`sendfile` включает быстрый путь для статики: первый запрос на открытом
HTTP/1.1-соединении подглядывается до hyper, и простой `GET`/`HEAD` файла
отдаётся системным `sendfile(2)` без копирования через userspace. Быстрый
путь не используется для `Range`, `If-None-Match`, `If-Modified-Since`,
`Upgrade`, при наличии предсжатого `.br`/`.gz`, а также если у маршрута есть
`add_headers`/`remove_headers`, выключен `server_header` или задан
`Alt-Svc` — всё это уходит в hyper. Работает только на Linux. Файлы меньше
`sendfile_min_bytes` намеренно идут обычным потоковым путём: на коротких телах
стоимость `sendfile`-обвязки выше выигрыша. Быстрый путь обслуживает только
первый запрос соединения; дальнейшие keep-alive запросы обрабатывает hyper.

`proxy_protocol` включает разбор заголовка PROXY до TLS и до HTTP. Поддержаны
версии 1 и 2. Заголовок при этом обязателен: соединение без него закрывается
без ответа. Включайте только тогда, когда порт доступен исключительно через
балансировщик — иначе клиент подделает свой адрес, а он попадает в логи,
`X-Forwarded-For` и rate limiter. Заголовок читается с `peek`, поэтому первые
байты HTTP не съедаются при ошибке.

`error_pages` на верхнем уровне задаёт запасные страницы для статусов, которые
не покрыты `error_pages` маршрута. Они применяются и к локальным ответам:
`404` без маршрута, `401`/`403` от auth и ACL, `429` от лимитера, ошибки
upstream. Нужен `error_root`; задавать их можно только вместе. Если у маршрута
есть своя страница для того же статуса, она важнее глобальной. Заголовки
`WWW-Authenticate`, `Retry-After` и `Allow` сохраняются.

## `[limits]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `max_headers` | целое > 0 | `64` | максимум заголовков в запросе (HTTP/1.1) |
| `max_header_bytes` | целое ≥ 8192 | `16384` (16 КиБ) | предел буфера заголовков |
| `upstream_timeout_secs` | целое, секунды | `30` | таймаут ожидания заголовков ответа upstream |
| `upstream_connect_timeout_secs` | целое > 0 | `5` | таймаут TCP/TLS-соединения с upstream |
| `upstream_send_timeout_secs` | целое, секунды | `0` | прервать запись тела в upstream без прогресса; `0` выключает |
| `max_connections` | целое > 0 | `1024` | одновременные клиентские соединения |
| `idle_timeout_secs` | целое, секунды | `60` | закрытие простаивающего keep-alive соединения |
| `keepalive_requests` | целое ≥ 0 | `1000` | закрыть соединение после стольких запросов; `0` — без предела |
| `lingering_close` | bool | `true` | дочитать входящие байты перед закрытием |
| `lingering_timeout_secs` | целое, секунды | `5` | предел дочитывания при lingering close |
| `reset_timedout_connection` | bool | `false` | отправлять RST вместо FIN при таймауте |
| `max_body_bytes` | целое ≥ 0 | `0` | `413`, если `Content-Length` больше; `0` — без лимита |
| `limit_rate` | целое ≥ 0 | `0` | байт/сек на ответ; `0` выключает |
| `limit_rate_after` | целое ≥ 0 | `0` | сколько байт отдать без ограничения |
| `open_file_cache` | целое ≥ 0 | `0` | кэшировать метаданные стольких файлов; `0` выключает |
| `open_file_cache_ttl_secs` | целое | `30` | время жизни метаданных в кэше |
| `requests_per_second` | целое ≥ 0 | `0` | токенов в секунду на IP; `0` — лимит выключен |
| `burst` | целое ≥ 0 | `0` | запас токенов; `0` — равен `requests_per_second` |
| `trusted_proxies` | список CIDR | `[]` | кому разрешено дополнять `X-Forwarded-For` |
| `request_body_timeout_secs` | целое, секунды | `30` | закрыть клиента, который перестал присылать тело; `0` выключает |
| `client_header_timeout_secs` | целое, секунды | `30` | закрыть клиента, который не прислал заголовки; `0` выключает |
| `upstream_body_timeout_secs` | целое, секунды | `30` | прервать upstream, который перестал отдавать тело |
| `websocket_idle_secs` | целое, секунды | `3600` | закрыть websocket/CONNECT после простоя; `0` выключает |
| `max_response_bytes` | целое > 0 | `67108864` | предел потокового ответа FastCGI/CGI |
| `max_upstream_response_bytes` | целое ≥ 0 | `0` | предел ответа проксируемого upstream; `0` — без лимита |
| `connection_drain_secs` | целое > 0 | `5` | сколько ждать дозавершения соединения при остановке |
| `shutdown_timeout_secs` | целое > 0 | `15` | общий предел остановки листенера |
| `fastcgi_pool_idle` | целое ≥ 0 | `16` | idle-соединений FastCGI на бэкенд |
| `fastcgi_pool_idle_secs` | целое | `30` | TTL idle-соединения FastCGI |
| `response_buffer_bytes` | целое ≥ 0 | `0` | буферизовать ответ upstream до этого размера; `0` — потоком |
| `request_buffer_bytes` | целое ≥ 0 | `0` | буферизовать тело запроса в памяти до этого размера |
| `request_spool_bytes` | целое ≥ 0 | `0` | крупные тела запроса писать во временный файл до этого размера |
| `response_spool_bytes` | целое ≥ 0 | `0` | крупные ответы до этого размера писать во временный файл; `0` — выключено |
| `spool_budget_bytes` | целое ≥ 0 | `0` | общий объём spool-файлов; `0` — без глобального лимита |

Подробности:

- `max_headers` передаётся в `http1::Builder::max_headers`. На HTTP/2 и HTTP/3 он
  не действует: там ограничение задаётся размером списка заголовков.
- `max_header_bytes` работает как `max_buf_size` для HTTP/1.1 и как
  `max_header_list_size` для HTTP/2. Слишком большой запрос получает `431`.
  Значение меньше `8192` отклоняется при загрузке: hyper не умеет работать с
  буфером меньше и паниковал бы внутри каждого соединения.
- `upstream_timeout_secs` ограничивает ожидание заголовков ответа upstream'а,
  чтение заголовков при `Upgrade` и запись заголовков в upstream при upgrade.
  По истечении — `504 Gateway Timeout` (для туннелей — `502`).
- `upstream_connect_timeout_secs` ограничивает только TCP- и TLS-рукопожатие с
  upstream, включая DNS-резолвинг в `HttpConnector`. Медленный, но уже
  установленный ответ этим таймаутом не обрезается.
- `upstream_send_timeout_secs` — idle-таймаут между порциями тела запроса,
  которые Elira пишет в upstream. Он не ограничивает общее время загрузки и не
  действует на ответ.
- `max_connections` — семафор в цикле accept. При достижении лимита новый сокет
  просто закрывается, без ответа и без очереди; событие пишется в лог на уровне
  `debug`. То же число независимо ограничивает количество одновременных
  туннелей (`CONNECT` и `Upgrade`): у них свой семафор с этим же значением.
- `idle_timeout_secs` закрывает keep-alive соединение, если по нему не пришло
  ни одного запроса за указанное время. `0` отключает этот таймер полностью.
  Таймер сбрасывается в момент прихода запроса, а не окончания ответа.
- `keepalive_requests` ограничивает число запросов на одном клиентском
  соединении. После этого ответ получает `Connection: close`; `0` оставляет
  соединение открытым до `idle_timeout_secs`.
- `lingering_close` после конца HTTP-соединения отправляет FIN и дочитывает
  входящие байты, чтобы клиент успел получить ответ, а не RST. Не больше
  `lingering_timeout_secs`; `false` закрывает сразу. С
  `reset_timedout_connection = true` соединение, закрытое по idle/header
  timeout, получает `SO_LINGER(0)` и RST.
- `max_body_bytes` проверяет `Content-Length`, а для потокового тела считает
  фактические байты и обрывает запрос с `413`, когда предел превышен. Это
  работает и для проксирования, и для FastCGI/CGI/module: лимит применяется
  до того, как тело уйдёт дальше.
- `limit_rate` ограничивает скорость отдачи ответа в байтах в секунду для
  проксирования, статики и приложений. `limit_rate_after` освобождает первые
  байты от ограничения. Маршрут может переопределить оба значения
  (`limit_rate = 0` отключает лимит для маршрута).
- `open_file_cache` кэширует результаты `stat` для статики: путь, метаданные и
  время проверки. Дескрипторы не переиспользуются — тело по-прежнему читается
  из файла. `open_file_cache_ttl_secs` задаёт срок жизни записи; `0` в
  `open_file_cache` выключает кэш.
- `max_upstream_response_bytes` защищает от «тяжёлого» бэкенда. Если
  `Content-Length` уже больше лимита, клиент сразу получает `502 upstream
  response too large`; иначе поток обрывается на том же пределе. `0` выключает
  проверку. Кэширование ответа с `Content-Length` выше лимита также
  отключается.
- `response_buffer_bytes` собирает ответ в память, если он не больше лимита.
  `response_spool_bytes` добавляет дисковую буферизацию: ответы больше
  `response_buffer_bytes`, но не больше этого лимита, пишутся в уже удалённый
  временный файл, и сокет upstream освобождается до того, как медленный клиент
  вычитает тело. Трейлеры сохраняются. `0` выключает диск. Счётчик
  `spooled` виден в `/status`.
- `request_buffer_bytes` и `request_spool_bytes` делают то же для тела запроса:
  маленькое тело собирается в памяти, крупное пишется во временный файл.
  Клиентский сокет освобождается раньше, а идемпотентные `PUT`/`DELETE` можно
  повторять при ошибке соединения, потому что у прокси остаётся копия тела.
  Тело без `Content-Length` тоже буферизуется до этих лимитов; если тело (с
  известной длиной или chunked) их превышает, уже прочитанный префикс отдаётся
  вместе с остатком исходного потока, поэтому запрос не ломается, но становится
  неретраибельным. Диск использует общий `spool_budget_bytes`; если бюджет
  занят, тело стримится или уходит в чейн из префикса и остатка.
- `spool_budget_bytes` ограничивает суммарный объём всех spool-файлов. Если
  ответ не помещается в свободный бюджет, он не ждёт, а стримится напрямую.
  `0` снимает глобальный лимит. Текущий расход виден в `/status` как
  `spool_used`; бюджет освобождается, когда тело дочитано или клиент
  отключился.
- `requests_per_second` включает token bucket на каждый IP. Превышение даёт
  `429` с `Retry-After: 1`. `burst` — глубина ведра; при `0` она равна
  `requests_per_second`. `rate_delay = true` на маршруте вместо немедленного
  `429` ждёт следующего токена; очередь ограничена `burst`, после чего запрос
  всё равно получает `429`.
- `limit_conn` на маршруте ограничивает число одновременных запросов на ключ
  `limit_conn_key` (по умолчанию IP). Слот держится до конца тела ответа,
  поэтому медленная отдача не обходит лимит; сверх лимита — `503`.
- `trusted_proxies` — CIDR-блоки. Если peer входит в список, его
  `X-Forwarded-For` сохраняется и дополняется адресом peer'а. Для всех
  остальных заголовок заменяется адресом peer'а, а клиентские
  `X-Forwarded-*`/`Forwarded` отбрасываются.
- TLS-handshake ограничен 10 секундами. Остальные таймауты вынесены в
  конфиг: `client_header_timeout_secs`, `upstream_connect_timeout_secs`,
  `keepalive_secs`, `connection_drain_secs`.

## `[compression]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | сжатие, если клиент прислал `Accept-Encoding` |
| `min_bytes` | целое | `1024` | не сжимать тела меньше этого размера |

Статика сжимается на лету теми же настройками, если рядом нет предсжатого
`.br`/`.gz`; для `Range` и `HEAD` сжатие не применяется. Сжимаются только
`200 OK` с типом `text/*`, `application/json`,
`application/javascript`, `application/xml`, `application/rss+xml`,
`application/atom+xml`, `image/svg+xml`. Исключения: `HEAD`, `206`, `304`,
ответы с уже выставленным `Content-Encoding`.

Предпочитается `br`, если клиент его принимает, иначе `gzip`. При сжатии
выставляется соответствующий `Content-Encoding`, добавляется
`Vary: Accept-Encoding`, а `Content-Length` снимается: тело идёт chunked.
Сжатие потоковое, поэтому заранее длину ответа посчитать нельзя.

## `[tls]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `cert` | путь | нет, обязательно | PEM-цепочка сертификатов |
| `key` | путь | нет, обязательно | PEM-приватный ключ |
| `client_ca` | путь | нет | PEM-корни для проверки клиентских сертификатов |
| `client_crl` | путь | нет | PEM-списки отзыва клиентских сертификатов |
| `client_auth` | `off` \| `optional` \| `required` | `off` | запрашивать ли клиентский сертификат |
| `backend` | `rustls` \| `openssl` | `rustls` | TLS-стек для TCP/unix-листенеров |
| `min_version` | `tls10` \| `tls11` \| `tls12` \| `tls13` | `tls12` | минимальная версия TLS |
| `ticket_key` | путь | нет | 32-байтовый ключ для общих TLS-тикетов между воркерами |
| `cipher_suites` | массив строк | по умолчанию rustls | cipher suites в порядке предпочтения |
| `curves` | массив строк | по умолчанию rustls | key exchange groups в порядке предпочтения |
| `ocsp` | путь | нет | DER OCSP-ответ для stapling; перечитывается по SIGHUP |
| `ocsp_hook` | путь | нет | команда, обновляющая OCSP-файлы; после неё идёт reload |
| `ocsp_refresh_secs` | целое > 0 | `86400` | период вызова `ocsp_hook` |
| `session_tickets` | целое ≥ 0 | `2` | TLS 1.3 tickets на handshake |
| `session_cache` | целое ≥ 0 | `256` | записей resumption-кэша; `0` выключает |
| `ticket_key` | путь | нет | общий 32-байтовый ключ тикетов для всех воркеров |
| `certificates` | массив таблиц | `[]` | дополнительные сертификаты по SNI |
| `reject_unknown_sni` | bool | `false` | отклонять handshake с неизвестным/пустым SNI |
| `verify_ocsp` | bool | `false` | проверять подпись и статус stapled OCSP |

Элемент `certificates`:

| Поле | Тип | Обязательно | Что делает |
| --- | --- | --- | --- |
| `cert` | путь | да | PEM-цепочка |
| `key` | путь | да | PEM-ключ |
| `names` | массив строк | да | точные имена или `*.example.com` |
| `ocsp` | путь | нет | DER OCSP-ответ для этого сертификата |

Секция включает TLS на основном TCP-листенере. Если `[tls]` нет, тот же порт
обслуживает обычный HTTP; отдельного «редиректа на HTTPS» нет, и один порт не
может одновременно принимать и TLS, и открытый HTTP.

- Пара `cert`/`key` необязательна, если задан `certificates`: она служит
  сертификатом по умолчанию для клиентов без SNI. Без пары и без
  `certificates` загрузка падает.
- Имя может встречаться в нескольких `certificates`, чтобы держать RSA и ECDSA
  варианты одного имени: Elira выбирает ключ, совместимый с signature
  algorithms клиента. `*.example.com` совпадает ровно с одним уровнем
  (`a.example.com`), но не с `a.b.example.com` и не с самим `example.com`.
  Если SNI не совпал, берётся сертификат по умолчанию.
- `reject_unknown_sni = true` отклоняет handshake, если SNI отсутствует или не
  совпал ни с одним именем; сертификат по умолчанию в этом случае не
  используется. Нужен хотя бы один `certificates`, иначе загрузка падает.
- `ocsp` внутри `certificates` задаёт отдельный OCSP-ответ для этого имени.
  `ocsp_hook` может обновлять и его; reload перечитывает все файлы. Без
  default-`ocsp` hook разрешён, если OCSP задан хотя бы одному SNI-сертификату.
- `session_tickets`/`session_cache` управляют resumption. `ticket_key` задаёт
  32-байтовый ключ, которым шифруются stateless TLS 1.3 tickets; один и тот же
  файл у всех воркеров делает resumption рабочим независимо от того, какой
  процесс принял соединение. Если файла нет, он создаётся с правами `0600`;
  файл с более широкими правами или неверной длиной отклоняется. Та же опция
  есть в `[http3]`.
- `verify_ocsp = true` проверяет stapled OCSP при загрузке: подпись против
  издателя из цепочки и статус `GOOD` для листового сертификата. Ошибка
  отменяет сборку runtime.
- Отсутствующие файлы и битый PEM — ошибка сборки runtime, то есть до accept.
- `backend = "openssl"` включает OpenSSL для TCP и unix-листенеров. Он нужен
  для `min_version = "tls10"` или `"tls11"`; rustls такие версии не умеет и
  загрузка с ними падает. OpenSSL-бэкенд поддерживает SNI-сертификаты, mTLS,
  CRL, OCSP, ALPN, `cipher_suites`, `curves`, `session_tickets` и
  `session_cache`. Общий `ticket_key` тоже поддерживается: файл из 32 байт
  детерминированно раскладывается в ключи OpenSSL. HTTP/3 всегда остаётся на
  rustls, потому что QUIC требует TLS 1.3.
- `cipher_suites` и `curves` задаются именами из rustls, например
  `TLS13_AES_128_GCM_SHA256`, `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`,
  `X25519`, `secp256r1`. Списки задают и порядок предпочтения. Пустой список
  отклоняется, неизвестное имя — ошибка сборки runtime. Для OpenSSL
  поддерживаются распространённые AES-GCM/CHACHA20/CBC suites и группы
  X25519/P-256/P-384/P-521. QUIC принимает только TLS 1.3 suites; иначе
  загрузка падает.
- ALPN предлагается в порядке `h2`, затем `http/1.1`. Клиент, поддерживающий
  оба, получит HTTP/2. HTTP/1.1 остаётся для клиентов без h2.
- `client_auth = "optional"` принимает клиентский сертификат, если он прислан
  и валиден, но пускает и без него. `required` без сертификата не пускает.
  Оба режима требуют `client_ca`; при `off` файл не читается вовсе.
- `client_crl` добавляет проверку отзыва. Файл — PEM с одним или несколькими
  CRL; пустой или битый файл отклоняется при сборке runtime. CRL применяется
  только при `client_auth = "optional"` или `"required"`; при `off` комбинация
  отклоняется. Обновлённый CRL подхватывается по `SIGHUP`.
- mTLS, SNI-сертификаты и их `ocsp` действуют и на QUIC-слушателе: `client_ca`,
  `client_auth` и `certificates` задаются в `[http3]` независимо от `[tls]`.
- Сертификат и ключ перечитываются по `SIGHUP`. Уже установленные соединения
  остаются на старом сертификате, новые используют новый. Если новые файлы
  битые, reload не применяется и работает старый конфиг.
- Приватный ключ в PEM распознаётся в вариантах, которые понимает
  `rustls-pemfile` (PKCS#8, PKCS#1, SEC1).

## `[acme]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `domains` | массив строк | обязателен | домены для сертификата |
| `contacts` | массив строк | обязателен | контакты ACME, `mailto:...` |
| `cache_dir` | путь | обязателен | кэш сертификатов и аккаунта |
| `production` | bool | `false` | `true` — Let's Encrypt, `false` — staging |
| `challenge` | `tls_alpn_01` \| `http_01` \| `dns_01` | `tls_alpn_01` | способ валидации |
| `http01_listen` | `IP:порт` | нет | отдельный plain-HTTP листенер для HTTP-01 |
| `dns_hook` | путь | нет | команда, публикующая TXT для DNS-01 |
| `dns_cleanup_hook` | путь | нет | команда, удаляющая TXT после валидации |
| `dns_propagation_secs` | целое | `30` | пауза после hook перед валидацией |

Сертификат получается по TLS-ALPN-01 прямо на основном TLS-листенере: порт
80 не нужен, но 443 должен быть доступен извне. `[acme]` и `[tls]` вместе —
ошибка. Сертификат продлевается в фоне; перезапуск не требуется.

Механизм проверен против Let's Encrypt staging и production на публичном
домене через реальный порт 443; staging удобен для проверки конфигурации без
production-лимитов. HTTP-01 требует, чтобы `listen` был на порту 80 либо был
задан `http01_listen`; токен отдаётся по
`/.well-known/acme-challenge/<token>` без TLS.

DNS-01 работает через внешний hook и поддерживает wildcard-имена. Команда
получает `DOMAIN`, `TXT_NAME`, `TOKEN` и `VALUE` в окружении и должна
опубликовать TXT-запись `TXT_NAME = VALUE`. После успешного exit Elira ждёт
`dns_propagation_secs`, затем просит CA проверить запись. Если задан
`dns_cleanup_hook`, после успешной выдачи он получает то же окружение плюс
`ACTION=cleanup` и должен удалить TXT-запись.

Для Cloudflare есть готовый hook `scripts/cloudflare-dns.sh`. Токену нужны
права `Zone:Read` и `DNS:Edit`; он читается из `CLOUDFLARE_API_TOKEN`, а не из
конфига. Положите его в root-only env-файл, например
`/etc/elira/cloudflare.env` с правами `0600`, и подключите через
`EnvironmentFile=` в systemd:

```toml
[acme]
domains = ["*.example.com"]
contacts = ["mailto:admin@example.com"]
cache_dir = "/var/lib/elira/acme"
production = true
challenge = "dns_01"
dns_hook = "/usr/local/lib/elira/cloudflare-dns.sh"
dns_cleanup_hook = "/usr/local/lib/elira/cloudflare-dns.sh"
```

Скрипт сам находит зону по самому длинному суффиксу `TXT_NAME`, публикует
`_acme-challenge...` с TTL 60 и при `ACTION=cleanup` удаляет запись. Учётные данные
аккаунта и сертификат кэшируются в `cache_dir`; обновление проверяется раз
в 12 часов.

## `[upstream_tls]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `insecure` | bool | `false` | не проверять сертификат и hostname upstream'а |
| `ca` | путь | нет | дополнительный PEM-корень к системным |
| `http2` | bool | `false` | предлагать `h2` в ALPN; HTTP/1.1 остаётся |
| `min_version` | `tls12` \| `tls13` | `tls12` | минимальная версия TLS до upstream |
| `client_cert` | путь | нет | PEM-сертификат для mTLS к upstream |
| `client_key` | путь | нет | PEM-ключ к `client_cert`; задаётся только вместе с ним |
| `client_crl` | путь | нет | PEM-списки отзыва для сертификата upstream |
| `cipher_suites` | массив строк | все rustls | TLS cipher suites в именах rustls |
| `curves` | массив строк | все rustls | key exchange groups в именах rustls |

Применяется ко всем upstream'ам с `tls = true`. `insecure` нужен только для
внутренних self-signed бэкендов. С `http2 = true` ALPN предлагает `h2` и
`http/1.1`; выбор делает upstream.

`client_cert` и `client_key` включают mutual TLS: Elira предъявляет этот
сертификат при подключении к upstream. Пара обязательна целиком — один
`client_cert` без ключа отклоняется при загрузке. С `client_crl` проверяется
отзыв сертификата upstream по перечисленным в PEM CRL; отозванный сертификат
даёт `502 Bad Gateway`.

`cipher_suites` и `curves` сужают политику TLS до upstream. Имена берутся из
rustls: например `TLS13_AES_128_GCM_SHA256` и `X25519`; регистр в именах групп
не важен. Неизвестное имя или пустой список останавливают загрузку. Без этих
полей остаются все suites и группы провайдера.

| `initial_stream_window_size` | целое ≥ 1024 | по умолчанию hyper | окно flow-control одного потока |

## `[http3]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `listen` | `IP:порт` | нет, обязательно | UDP-адрес QUIC-листенера |
| `cert` | путь | нет, обязательно непустое | PEM-сертификат для QUIC |
| `key` | путь | нет, обязательно непустой | PEM-ключ для QUIC |
| `client_ca` | путь | нет | PEM-корни клиентских сертификатов |
| `client_crl` | путь | нет | PEM-списки отзыва клиентских сертификатов |
| `client_auth` | `off` \| `optional` \| `required` | `off` | клиентские сертификаты на QUIC |
| `cipher_suites` | массив строк | по умолчанию rustls | TLS 1.3 suites для QUIC |
| `curves` | массив строк | по умолчанию rustls | key exchange groups для QUIC |
| `ticket_key` | путь | нет | общий 32-байтовый ключ тикетов |
| `certificates` | массив таблиц | `[]` | SNI-сертификаты на QUIC, формат как у `[tls]` |
| `reject_unknown_sni` | bool | `false` | отклонять QUIC-handshake с неизвестным/пустым SNI |
| `idle_timeout_secs` | целое > 0 | `30` | idle timeout QUIC-соединения |
| `max_concurrent_bidi_streams` | целое > 0 | по умолчанию quinn | одновременные двунаправленные потоки |
| `stream_receive_window` | целое > 0 | по умолчанию quinn | окно приёма одного потока |
| `receive_window` | целое > 0 | по умолчанию quinn | окно приёма соединения |
| `send_window` | целое > 0 | по умолчанию quinn | окно отправки соединения |
| `early_data` | bool | `false` | разрешить 0-RTT на QUIC (проверено session resumption-клиентом) |

HTTP/3 живёт на отдельном UDP-порту и не делит сокет с TCP-листенером.
`cert`/`key` здесь независимы от `[tls]`: их можно не задавать в `[tls]` вовсе,
если по TCP отдаётся открытый HTTP. Оба поля обязательны — при пустом значении
загрузка падает с `http3.cert must not be empty` / `http3.key must not be empty`.

- QUIC использует ALPN `h3`; других протоколов на этом сокете нет.
- Маршрутизация, проксирование, статика, access-лог и `CONNECT` те же, что и на
  TCP: h3-слушатель получает тот же `Proxy`. Отличие — отсутствие
  `Transfer-Encoding` и `Content-Length` в ответах: во фрейминге HTTP/3 они не
  нужны.
- По `SIGHUP` слушатель останавливается и поднимается заново с новым
  сертификатом. Живые QUIC-соединения при этом рвутся — в отличие от HTTP/1.1 и
  HTTP/2 на TCP, которые переживают reload.
- Если h3-сертификат битый, задача слушателя завершается с ошибкой в логе;
  остальной сервер продолжает работать, но HTTP/3 не поднимется до следующего
  успешного reload или рестарта.
- `max_headers` и `max_header_bytes` проверяются и на h3: HTTP/3-мост
  передаёт декодированные заголовки в общий прокси, который отвечает `431`,
  если число или суммарный размер превышает лимит. Проверка приблизительная:
  на каждый заголовок добавляется 4 байта служебного запаса, а не точный
  размер HPACK-блока.
- PROXY protocol v2 на QUIC разбирается до передачи датаграмм в quinn;
  транспортный peer остаётся адресом балансировщика, а адрес клиента из
  заголовка используется для логов, ACL и `X-Forwarded-For`.

## `[log]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `format` | `"text"` или `"json"` | `"text"` | формат строки access-лога |
| `template` | строка | нет | nginx-подобный шаблон; сильнее `format` |
| `sample` | дробь 0..1 | `1.0` | доля запросов, попадающих в access-лог |
| `syslog` | путь | нет | Unix datagram, обычно `/dev/log` |

`sample` применяется к каждому запросу независимо; `0.0` выключает запись,
`1.0` пишет всё. Решение принимается по уже случайному `request_id`, поэтому
метрики и ответы клиентам не зависят от сэмплирования. Маршрут может
переопределить долю через `access_log_sample`.

Значение сравнивается точно: только эти две строки. Любое
другое (включая `Text` или `JSON`) даёт ошибку `unknown log format "...", expected "text" or "json"`.
Формат читается на каждый запрос из текущего runtime, поэтому смена по `SIGHUP`
применяется и к уже открытым keep-alive соединениям.

Без `file` и `syslog` access-лог пишется в target `access` через `tracing`:
одна строка на запрос, с id запроса, методом, версией, Host, путём, статусом,
размером тела и временем. Формат `json` — та же запись в виде JSON-объекта.

Шаблон понимает `$remote_addr`, `$host`, `$request`, `$request_method`,
`$request_uri`, `$server_protocol`, `$status`, `$body_bytes_sent`,
`$http_user_agent`, `$http_referer`, `$request_time`, `$request_id`,
`$upstream`, `$upstream_addr`, `$upstream_status`, `$upstream_response_time`,
`$time_iso8601` и `$time_local`. Неизвестная переменная — ошибка загрузки,
литеральный доллар пишется как `$$`. Время сейчас всегда UTC. Имена из
`[[maps]]`, `[[geos]]` и `[[splits]]` тоже доступны как `$name`.

## `[health]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | включает активные проверки |
| `path` | строка | `"/health"` | путь, который опрашивается на каждом upstream |
| `method` | `"GET"` \| `"HEAD"` | `"GET"` | метод health-пробы |
| `expect_status` | массив кодов | `[]` | какие коды считать живыми; пусто — любые `2xx`/`3xx` |
| `host` | строка | адрес upstream'а | заголовок `Host` в пробе |
| `interval_secs` | целое > 0 | `5` | период между циклами проверок |
| `timeout_secs` | целое > 0 | `2` | таймаут на каждую операцию проверки |

Проверка — обычный HTTP/1.1 запрос `method path` с `Connection: close` на
адрес `servers` из upstream'а. Живым считается ответ `2xx`/`3xx` либо код из
`expect_status`; всё остальное, ошибка соединения и таймаут — «down».

- `path` должен начинаться с `/` и не содержать пробелов и управляющих
  символов; иначе ошибка `health.path must start with '/' ...`. Проверка пути
  выполняется только при `enabled = true`.
- `method` — только `GET` или `HEAD`. `expect_status` принимает коды
  `100..599`. `host` не может быть пустым или содержать пробелы.
- `health_path`, `health_method`, `health_expect_status` и `health_host` у
  upstream'а переопределяют глобальные значения независимо от `enabled`.
- `interval_secs` и `timeout_secs` тоже проверяются только при включённых
  проверках; ноль — ошибка.
- `timeout_secs` применяется отдельно к connect, записи запроса и чтению ответа,
  поэтому худший случай одной проверки — примерно три таймаута.
- `upstream` без health-проверок (или выключенные проверки) считаются живыми:
  сервер получает трафик, пока не начнёт отвечать ошибками на сами запросы.
- Fail-open: если проверка пометила down все серверы upstream'а, трафик всё
  равно идёт на один из них (по кругу), а не превращается в `503`. Один сломанный
  пробник не должен устраивать аварию.
- Down-сервер исключается из round-robin до следующей успешной проверки; обратно
  он возвращается сам, без рестарта.
- При выключенных проверках цикл просыпается раз в 30 с, ничего не опрашивает и
  считает все серверы живыми; метрики с числами up/down обновляются на каждом
  таком тике.
- По `SIGHUP` конфиг health применяется сразу, и перед публикацией нового
  runtime все upstream'ы проверяются один раз — чтобы после reload не было окна,
  в котором всё снова «здорово».

## `[connect]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | разрешает метод `CONNECT` |
| `allow` | массив строк | `[]` | точные `host:port`, куда разрешён туннель |

При `enabled = false` любой `CONNECT` получает `405 Method Not Allowed`.
При `enabled = true` список `allow` обязателен и не может быть пустым.

- Каждый элемент — ровно `host:port`, с портом. `10.0.0.5` без порта
  отклоняется, как и строка с `@` (userinfo) или `/`. IPv6 — в скобках:
  `[::1]:5432`.
- Сравнение с целью запроса — точное совпадение строки authority. Это не
  подсеть и не шаблон: `api.internal:443` не откроет `10.0.0.5:443` и не
  покроет другой порт.
- Почему это опасно: включённый без ограничений `CONNECT` превращает
  reverse-proxy в открытый релей, через который из интернета ходят во внутреннюю
  сеть и на localhost (SSRF-плечо). Обратному прокси такой режим обычно не нужен
  вовсе, поэтому по умолчанию он выключен. Список `allow` — единственная защита,
  других проверок назначения нет.
- Туннели ограничены тем же числом, что `limits.max_connections`, и
  `upstream_connect_timeout_secs` на установку соединения.
- `CONNECT` работает по HTTP/1.1, HTTP/2 и HTTP/3. Для HTTP/2 нужен TLS с
  ALPN `h2` или `h2c = true`; HTTP/3 использует QUIC-поток напрямую.
- Extended `CONNECT` с `:protocol` (WebTransport, WebSocket over HTTP/3) не
  является обычным TCP-туннелем и отвечает `501 Not Implemented`.
- WebSocket over HTTP/2 (RFC 8441) принимается как extended `CONNECT` с
  `:protocol = websocket` и проксируется в upstream как обычный HTTP/1.1
  `Upgrade`. Исходные `Sec-WebSocket-*` заголовки сохраняются.

## `[metrics]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `listen` | `IP:порт` | нет, обязательно | адрес отдельного HTTP-листенера метрик |
| `auth_file` | путь | нет | htpasswd; закрывает весь админский листенер |

Секция включает отдельный мини-листенер. `GET /metrics` отдаёт счётчики в
текстовом формате Prometheus (`text/plain; version=0.0.4`). `GET /status`
отдаёт JSON с upstream'ами, их серверами, health-флагами, числом активных
запросов и статистикой кэша.

| Метод и путь | Что делает |
| --- | --- |
| `GET /metrics` | счётчики Prometheus |
| `GET /status` | JSON-снимок |
| `GET /config` | эффективный конфиг в JSON |
| `POST /reload` | то же, что `SIGHUP` |
| `POST /drain` | graceful shutdown |
| `POST /cache/purge` | очистить кэш |

Любой другой путь или метод — `404`. Основной листенер эти пути не
обслуживает.

`GET /config` отдаёт то, что реально загружено после include и подстановки
окружения, а не исходный файл. В single-process режиме снимок берётся из
текущего runtime и меняется по `SIGHUP`; в worker-режиме супервизор обновляет
его при reload и рассылке SIGHUP. Секреты (`secure_link.secret`, `ajp_secret`,
значения `request_headers`) в JSON заменяются на `***`, как и чувствительные
значения `add_headers`. Пароли по-прежнему лежат в `auth_file`, а ключи TLS —
в файлах.

- Здесь нет TLS, лимитов соединений и таймаутов из `[limits]`.
- Слушайте loopback (`127.0.0.1:9090`), если счётчики не должны быть видны
  снаружи. `auth_file` включает Basic auth для всех путей, включая `/metrics`.
  Листенер не на loopback без `auth_file` не запустится.
- `POST /reload`, `/drain` и `/cache/purge` требуют заголовок
  `x-elira-admin: 1`; без него возвращается `403`.
- Адрес фиксируется при старте. Изменение `metrics.listen` по `SIGHUP`
  игнорируется с предупреждением в логе; добавление или удаление секции тоже
  требует рестарта.

## `[cache]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | кэш успешных `GET` |
| `ttl_secs` | целое | `60` | время жизни записи |
| `max_bytes` | целое | `67108864` (64 МиБ) | суммарный размер тел |
| `max_item_bytes` | целое | `1048576` (1 МиБ) | максимальное тело одной записи |
| `dir` | путь | нет | хранить тела на диске в этом каталоге |
| `shared` | bool | `false` | читать записи других процессов из `dir` |
| `stale_secs` | целое ≥ 0 | `0` | отдавать протухшее тело, пока идёт обновление |

`[cache.zones.NAME]` задаёт отдельную зону с независимыми `max_bytes`,
`max_item_bytes`, `ttl_secs`, `dir`, `stale_secs` и `shared`. Маршрут выбирает
зону через `cache_zone`; без него используется обычный `[cache]`. `cache_enabled
= false` на маршруте отключает кэш независимо от зоны. У каждой зоны свои
бюджет, вытеснение и загрузка дискового каталога при старте.

Кэшируются только `200 OK` на `GET` с известным `Content-Length` не больше
`max_item_bytes`, без `Set-Cookie` и без `Cache-Control: no-store/private`.
Ответы с неизвестной длиной не кэшируются: тело не буферизуется.
FastCGI, CGI и модульные ответы — исключение: они буферизуются до
`max_item_bytes`, а более крупное тело продолжает стримиться без записи в кэш.
`cache_valid` добавляет другие статусы, например
`[{ statuses = [404], ttl_secs = 60 }]`; для `200` по-прежнему действует
`cache_ttl_secs`/`ttl_secs`.

`cache_key` задаёт шаблон ключа, например `$host$uri`, и позволяет игнорировать
query. `cache_bypass` — список переменных; непустое значение, отличное от `0`,
обходит кэш на чтение и запись.

Ключ — нормализованный Host плюс путь с query. Ответ кэша отдаётся без
сжатия. `X-Cache` принимает `HIT`, `MISS` или `STALE`. Вытеснение: сначала
протухшие записи, затем самые старые по времени вставки.

`Vary` учитывается: под ключом хранится по записи на каждую комбинацию
заголовков. Запросы с `Authorization`/`Cookie` кэш обходят, ответы с
`Set-Cookie`, `no-store`, `private` и `no-cache` не сохраняются.
`s-maxage`/`max-age` сокращают `ttl_secs`, но не удлиняют его; если их нет,
используется `Expires` относительно `Date`. Просроченный `Expires` не
кэшируется. На ответе выставляется `Age`. `must-revalidate` запрещает отдачу
из stale-окна. Запрос с `Cache-Control: no-cache/no-store` или
`Pragma: no-cache` обходит кэш и не пополняет его.

С `stale_secs > 0` протухшая запись ещё отдаётся с `X-Cache: STALE`, а в фоне
запускается один запрос за свежей копией. Запрос условный: сохранённые `ETag`
и `Last-Modified` уходят как `If-None-Match`/`If-Modified-Since`, ответ `304`
продлевает TTL без повторной передачи тела. На время обновления ключ помечен,
поэтому параллельные запросы не создают лавину. Промахи тоже схлопываются:
один запрос заполняет ключ, остальные ждут до двух секунд и перечитывают кэш;
если заполнить не удалось, они идут в upstream сами. Кэшированный ответ на HIT
проходит то же сжатие, что и свежий.

С `dir` тела лежат в файлах вместе с метаданными, а в памяти остаются только
индексы. `shared = true` добавляет read-through: при промахе локального индекса
воркер ищет готовую запись в общем каталоге. Мутации каталога идут под
advisory-lock `.elira-cache.lock`, а `max_bytes` считается по всему каталогу:
после вставки самый старый файл удаляется, пока бюджет не сойдётся. Дубликаты
одного ключа всё ещё возможны, если два процесса пишут одновременно; чтение
берёт первый подходящий файл. Записи переживают перезапуск: протухшие и битые файлы удаляются при
загрузке, бюджет `max_bytes` применяется сразу. Один файл на запись;
`max_bytes` по-прежнему считает тела, а не файловые блоки.

## `[resolver]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `ttl_secs` | целое | `30` | сколько кэшировать успешный ответ DNS |
| `negative_ttl_secs` | целое ≥ 0 | `5` | сколько кэшировать пустой/неудачный ответ; `0` выключает |
| `hosts` | массив таблиц | `[]` | статические записи `{ name, addresses }` |

Резолвер общий для обычного клиента, health-проб, HTTP/2- и HTTP/3-пулов.
`ttl_secs = 0` отключает кэш положительных ответов, но не мешает
`negative_ttl_secs`. Статические записи сравниваются без учёта регистра и
завершающей точки и не требуют наличия имени в системе:

```toml
[[resolver.hosts]]
name = "backend.test"
addresses = ["10.0.0.5", "10.0.0.6"]
```

Пустой список адресов и повторяющееся имя — ошибка загрузки.

## `[[upstreams]]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `name` | строка | нет, обязательна | имя, на которое ссылаются маршруты |
| `servers` | массив строк или таблиц | нет, обязателен и непуст | адреса бэкендов `host:port`, `unix:/path` или таблицы с опциями |
| `weights` | массив целых > 0 | `[]` (все 1) | относительные веса для `round_robin` и `least_conn` |
| `balance` | `round_robin` \| `least_conn` \| `hash` \| `random` | `round_robin` | как выбирать сервер |
| `hash_key` | строка | `"ip"` | ключ для `balance = "hash"`: `ip`, `authorization`, `header:NAME`, `cookie:NAME`, `uri` |
| `retries` | целое 0..5 | `0` | дополнительные попытки на ошибку соединения |
| `retry_on` | массив строк | `["error","timeout"]` | условия повтора: `error`, `timeout`, коды 5xx |
| `tls` | bool | `false` | подключаться к серверам по HTTPS |
| `sni` | строка | нет | имя для SNI и проверки сертификата |
| `health_path` | путь | `health.path` | свой путь health-пробы |
| `health_method` | `GET` \| `HEAD` | `health.method` | метод пробы |
| `health_expect_status` | массив кодов | `health.expect_status` | ожидаемые коды |
| `health_host` | строка | `health.host` | свой `Host` в пробе |
| `tls_insecure` | bool | `[upstream_tls] insecure` | не проверять сертификат |
| `tls_ca` | путь | `[upstream_tls] ca` | свой PEM-корень |
| `http2` | bool | `[upstream_tls] http2` | предлагать `h2` |
| `bind` | IP | нет | локальный адрес для исходящих соединений |
| `proxy_protocol` | bool | `false` | PROXY protocol v1 перед upstream-соединением |
| `dns_ttl_secs` | целое > 0 | `30` | предел жизни соединения в пуле; имя резолвится заново при новом соединении |
| `keepalive` | целое ≥ 0 | без предела | сколько idle-соединений держать на хост; `0` выключает переиспользование |
| `keepalive_secs` | целое > 0 | `dns_ttl_secs` | сколько живёт простаивающее соединение |
| `keepalive_requests` | целое ≥ 0 | `0` | пересоздать пул после стольких запросов; `0` — без ротации |
| `h1_pool` | bool | `false` | собственный HTTP/1.1 keep-alive пул |
| `h2_pool` | bool | `false` | собственный HTTP/2-пул Elira; на plain TCP — h2c prior knowledge |
| `h3_pool` | bool | `false` | собственный HTTP/3-пул; требует `tls = true` |
| `failures_before_eject` | целое ≥ 0 | `0` | сколько транспортных ошибок подряд до пассивного отключения |
| `eject_secs` | целое > 0 | `30` | на сколько секунд отключать сервер |

- `name` не может быть пустым или повторяться.
- `servers` не может быть пустым; каждый элемент — `host:port` с портом
  или `unix:/абсолютный/путь.sock`. Допустимы DNS-имена и IP; IPv6 — в
  скобках. Строки с `@` или `/` без префикса `unix:` отклоняются.
- Элемент `servers` может быть таблицей:
  `{ address = "10.0.0.5:8080", backup = true, down = false, max_conns = 20, slow_start_secs = 30 }`.
  `backup` получает трафик только когда все основные серверы недоступны;
  `down` исключает сервер полностью; `max_conns` ограничивает одновременные
  запросы (`0` — без лимита); `slow_start_secs` плавно возвращает вес сервера
  после восстановления. Если все серверы помечены `down`, конфиг не загрузится.
- Unix-сокет говорит по HTTP/1.1 без TLS. `tls = true` вместе с `unix:` —
  ошибка загрузки.
- `bind` задаёт локальный IP для исходящих TCP-соединений: обычного клиента,
  health-проб, собственного HTTP/2-пула и upgrade-туннелей. Для `h3_pool`
  этот же адрес привязывается к QUIC-endpoint. Адрес должен существовать на
  хосте; иначе соединения завершаются ошибкой.
- `proxy_protocol = true` пишет PROXY protocol v1 перед HTTP или TLS. В
  заголовке — адрес клиента и фактический адрес upstream'а; при разных
  семействах адресов отправляется `PROXY UNKNOWN`. Заголовок привязан к
  клиентскому соединению, поэтому такой upstream не переиспользует соединения
  из пула и говорит по HTTP/1.1. Не сочетается с `h3_pool` и `unix:`-серверами;
  upgrade-туннели тоже получают заголовок.
- `round_robin` идёт по кругу, пропуская серверы, помеченные health-проверкой
  как мёртвые. `least_conn` выбирает живого с наименьшим числом активных
  запросов; счётчик держится от приёма запроса до возврата заголовков ответа,
  поэтому потоковое тело в нём уже не учитывается.
- `weights` задаёт относительную нагрузку: `[3, 1]` отправляет три запроса из
  четырёх на первый сервер и один на второй. `round_robin` раскладывает слоты
  по весам, `least_conn` сравнивает `active / weight`. Веса должны совпадать по
  длине с `servers`, быть больше нуля, а сумма — не больше 10000. С
  `balance = "hash"` веса не сочетаются.
- `balance = "random"` выбирает сервер псевдослучайно; веса учитываются.
- `keepalive` ограничивает число простаивающих соединений на хост, а
  `keepalive_secs` — время их жизни. Ноль в `keepalive` отключает
  переиспользование; `keepalive_secs` по умолчанию берётся из `dns_ttl_secs`.
- `keepalive_requests` пересоздаёт legacy-клиент после указанного числа
  запросов, закрывая его idle-соединения. Это приближение nginx-семантики:
  hyper не отдаёт счётчик запросов на конкретное соединение. Активные запросы
  доигрывают на старом клиенте.
- `balance = "hash"` использует rendezvous hashing: один и тот же `hash_key`
  остаётся на одном сервере, а добавление или удаление сервера перераспределяет
  только ключи, которые были на нём. `hash_key = "uri"` хеширует путь с query;
  остальные формы такие же, как у `rate_key`. При отсутствии заголовка или
  cookie ключом становится IP. Если все серверы отключены, hash всё равно
  выбирает детерминированного победителя, не теряя привязку.
- `hash_key` допустим только вместе с `balance = "hash"`.
- `retries` работает для `GET`, `HEAD`, `OPTIONS` без тела, а также для
  `PUT`/`DELETE`, если тело буферизовано через `request_buffer_bytes` или
  `request_spool_bytes`. `retry_on` выбирает условия: `error`, `timeout` и/или
  коды `500..599`; пустой список оставляет значения по умолчанию — `error` и
  `timeout`. Повтор по 5xx отбрасывает уже полученный ответ и идёт на другой
  сервер, поэтому включайте его только для идемпотентных маршрутов.
- Все серверы помечены мёртвыми — трафик всё равно идёт (fail-open), иначе
  сломанная проверка превратилась бы в простой.
- `failures_before_eject` включает пассивную эвикцию: после указанного числа
  подряд ошибок соединения или таймаутов сервер пропускается на `eject_secs`.
  HTTP-ответы, включая `5xx`, ошибкой не считаются. Успешный запрос сбрасывает
  счётчик и снимает эвикцию; если отключены все серверы, выбор всё равно
  возвращается к ним (fail-open). Текущее время эвикции видно в `/status` как
  `ejected_for_ms`.
- `h1_pool = true` использует собственный HTTP/1.1 keep-alive пул: до 64
  соединений на origin, соединение возвращается в пул только после конца тела
  ответа. Не сочетается с `h2_pool`/`h3_pool` и `unix:`-серверами.
- `h3_pool = true` использует QUIC/h3-пул (SNI, ALPN h3, до 4 соединений);
  статистика connections/active/total видна в `/status`.
- `h2_pool = true` заменяет legacy-клиент на собственный HTTP/2-пул: до
  четырёх соединений на origin, least-busy выбор, реальные счётчики
  connections/active/total/queued в `/status`. Для `http://` используется h2c
  prior knowledge, для `https://` обязателен ALPN h2.
- Hyper резолвит имя при каждом новом соединении. `dns_ttl_secs` ограничивает
  время жизни соединения в пуле, поэтому смена DNS видна не позже этого
  значения (по умолчанию 30 секунд).
- С `tls = true` соединение идёт по HTTPS; `sni` нужен, когда в `servers` стоит
  IP, а сертификат выписан на имя. Health-проба для TLS-бэкенда делает настоящее
  рукопожатие теми же настройками доверия; для unix-сокета проба идёт по нему.
- Health-флаги сбрасываются при сборке нового runtime, но при включённых
  проверках reload сначала опрашивает серверы, а потом публикует новое
  состояние.
- Один upstream можно использовать в нескольких маршрутах.

## `[[streams]]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `listen` | `IP:порт` | обязательно | адрес L4-листенера |
| `transport` | `tcp` \| `udp` | `tcp` | транспорт |
| `upstreams` | массив строк | обязательно, непусто | адреса `host:port` |
| `balance` | `round_robin` \| `least_conn` \| `hash` | `round_robin` | выбор upstream; hash — по IP клиента |
| `tls` | bool | `false` | терминировать TLS на TCP-листенере |
| `connect_timeout_secs` | целое > 0 | `5` | таймаут подключения к upstream |
| `idle_timeout_secs` | целое ≥ 0 | `300` | простой TCP-туннеля или UDP-сессии; `0` выключает |

TCP-поток копирует байты в обе стороны, переподключаясь к следующему
upstream при ошибке соединения. `tls = true` использует сертификаты, SNI и
mTLS из `[tls]`/`[acme]`; ALPN для L4 не важен. UDP-сессии привязаны к адресу
клиента, получают отдельный сокет к upstream и истекают по `idle_timeout_secs`.
`transport = "udp"` с `tls = true` отклоняется.

## `[[rewrites]]`

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `pattern` | regex | обязателен | шаблон по пути запроса |
| `replacement` | строка | обязателен | замена с `$1`/именованными группами |
| `flag` | `last` \| `break` \| `redirect` \| `permanent` | `last` | что делать после совпадения |

Правила применяются к пути до выбора маршрута. `last` перезапускает список с
новым путём (не более 10 раз), `break` оставляет новый путь и прекращает
rewrite, `redirect`/`permanent` отвечают `302`/`301` с `Location`. Замена
понимает `$1..$9`, именованные группы и `$$`. Query-строка сохраняется, если
замена не содержит `?`.

## `[[maps]]`

```toml
[[maps]]
name = "tenant"
source = "$http_x_tenant"
default = "guest"
values = { acme = "gold", beta = "silver" }
```

`name` становится новой переменной `$tenant`. `source` — существующая
переменная с ведущим `$`; её значение ищется в `values`, иначе берётся
`default`, иначе пустая строка. Мапы вычисляются по порядку, поэтому более
поздняя может ссылаться на предыдущую. `name` должен быть идентификатором,
имена не повторяются.

## `[[geos]]` и `[[splits]]`

```toml
[[geos]]
name = "zone"
default = "other"
values = { "10.0.0.0/8" = "internal", "192.168.0.0/16" = "lan" }

[[splits]]
name = "variant"
source = "$remote_addr"
buckets = [{ percent = 10, value = "a" }, { percent = 90, value = "b" }]
```

`geos` выбирает значение по адресу клиента; при пересечении сетей побеждает
самый длинный префикс. `splits` хеширует значение `source` в 0..99 и идёт по
накопленным процентам; сумма процентов не больше 100, остаток даёт пустую
строку. Имена общие с `[[maps]]` и не повторяются.

Правила:

- Нужна ровно одна цель: `upstream`, `root`, `redirect`, `fastcgi_pass`,
  `cgi_pass` или `module`. Две сразу — ошибка, ни одной — `route N needs
  exactly one`.
- `module_sandbox` запускает `.so` в дочернем процессе `elira
  module-worker`; путь к раннеру можно переопределить `ELIRA_MODULE_RUNNER`.
  Это изоляция падений и FFI-ошибок, но не смена пользователя и не namespace:
  дочерний процесс сохраняет права сервера.
- `fastcgi_pass` требует `fastcgi_root`; `SCRIPT_FILENAME` собирается из
  корня, пути запроса и `fastcgi_index` для каталога. `cgi_pass` и `module`
  должны быть абсолютными путями. Модуль загружается при старте и работает
  в процессе сервера.
- FastCGI и CGI передают тело запроса и ответа потоком с backpressure;
  `max_response_bytes` ограничивает ответ, `max_concurrent` — число
  одновременных app-запросов. Модули `.so` загружаются только с
  не-world-writable пути.
- `ocsp_hook` выполняется при старте (до сборки TLS) и затем раз в
  `ocsp_refresh_secs`; после успешного обновления файла конфиг
  перезагружается, и новый ответ попадает в stapling. При `workers > 1` hook
  запускает супервизор и рассылает SIGHUP воркерам.
- `workers > 1` запускает супервизор и N процессов; каждый слушает тот же
  порт через `SO_REUSEPORT`. SIGUSR2 перезапускает воркеры по одному,
  SIGHUP рассылается всем и может добавить воркеров, если новое значение
  больше; уменьшение требует рестарта. Счётчики воркеров раз в секунду уходят
  супервизору по Unix datagram, и именно он отдаёт агрегированные `/metrics`
  и `/status` (снимок каждого воркера отдельно). `POST /reload` рассылает SIGHUP воркерам, `POST /drain`
  останавливает группу, `POST /cache/purge?prefix=host/path` будит очистку
  кэша во всех воркерах.
- `host` сравнивается без учёта регистра, без порта и без завершающей точки.
  `Example.COM:8080` попадёт в маршрут `example.com`. Host с userinfo
  (`admin:80@example.com`) и некорректным портом отклоняется с `400`.
- `host = "*.example.com"` совпадает с поддоменами (`api.example.com`), но не
  с самим `example.com`. Звёздочка допустима только в начале.
- `host = "*"` — маршрут по умолчанию. Таких может быть несколько, если у них
  разные `path`; повтор пары `(host, path)` — ошибка `route for host ... is
  defined twice`.
- `path` — префикс, а не регулярка. `/api` совпадает с `/api` и `/api/users`,
  но не с `/apix`. Внутри одного host выбирается самый длинный подходящий
  префикс; маршрут без `path` играет роль `/`. `match = "exact"` требует
  полного совпадения пути. `no_regex = true` на префиксе отключает проверку
  regex для этого host, как `^~`.
- `path_regex` проверяется после префиксных маршрутов того же host, но
  проигрывает точному `match = "exact"` и префиксу с `no_regex`.
  `path` и `path_regex` взаимоисключающие; с regex нельзя использовать
  `strip_prefix`. Битое выражение отклоняется при загрузке.
- `strip_prefix` (только с `upstream`) убирает совпавший префикс:
  `/api/users` при `path = "/api"` уходит на бэкенд как `/users`.
- `redirect` отвечает `301`, `302`, `303`, `307` или `308` с `Location` из
  `to`, не трогая upstream. Другие статусы отклоняются при загрузке.
- `add_headers` и `remove_headers` применяются к ответу после проксирования
  или статики. Формат `add_headers` — `"Name: value"`; строка без двоеточия
  или с невалидным именем отклоняется.
- `proxy_hide_header` убирает заголовки upstream-ответа; `proxy_pass_header`
  возвращает конкретный скрытый заголовок. `proxy_redirect` заменяет префикс
  в `Location` и `Refresh`, `proxy_cookie_domain`/`proxy_cookie_path` —
  атрибуты `Domain`/`Path` в `Set-Cookie`.
- `request_headers` заменяет одноимённые заголовки клиента перед отправкой в
  upstream, `request_remove_headers` удаляет их. Значения могут содержать
  переменные (см. ниже).
  `Host`, `X-Forwarded-*` и `X-Request-Id` формируются автоматически, но
  `request_headers` может переопределить их явно. Hop-by-hop и framing
  заголовки (`Connection`, `Transfer-Encoding`, `Content-Length`, `Upgrade`,
  `TE`, `Trailer`, `Keep-Alive`, `Proxy-Connection`) менять нельзя — конфиг
  отклоняется.
- В значениях `request_headers`, `add_headers`, `redirect.to`, `return.body`,
  `return.content_type` и путях `error_pages` подставляются переменные: `$remote_addr`, `$host`, `$uri`,
  `$request_uri`, `$query_string`/`$args`, `$request_method`, `$scheme`,
  `$server_port`, `$request_id`, `$http_NAME`, `$cookie_NAME` и имена из
  `[[maps]]`/`[[geos]]`/`[[splits]]`. Форма `${NAME}` поддерживается, `$$` даёт
  литеральный `$`. Неизвестная переменная остаётся
  как есть. Если после подстановки значение не является допустимым
  HTTP-заголовком, заголовок пропускается, а редирект отвечает `500`.
- `return = { status, body, content_type }` отвечает фиксированным статусом.
  `body` и `content_type` раскрывают переменные. Для `204` и `304` тело не
  отправляется. Это отдельная цель маршрута и не сочетается с `upstream`,
  `root`, `alias` или `redirect`.
- `if = [{ variable = "$http_x_debug", equals = "1", return = { status = 503, body = "blocked" } }]`
  проверяет переменную до выбора цели маршрута. Нужно ровно одно из `equals`
  или `matches` (regex) и `return`. Условия вычисляются по порядку, первое
  совпадение отвечает и завершает запрос.
- `[[routes.locations]]` вкладывает location в предыдущий маршрут. Путь
  ребёнка складывается с путём родителя: `/app` и `/admin` дают
  `/app/admin`. `host`, `listeners`, цель и незаданные опции наследуются.
  Родитель без собственной цели работает только как группа и в итоговую
  таблицу не попадает. Regex-ребёнок сохраняет префикс родителя и матчится
  только под ним. Вложенность ограничена 16 уровнями.

  ```toml
  [[routes]]
  host = "example.com"
  path = "/app"
  upstream = "app"

  [[routes.locations]]
  path = "/admin"
  upstream = "admin"

  [[routes.locations]]
  path_regex = "\\.php$"
  upstream = "php"
  ```
- `name = "@fallback"` объявляет именованный location. Он не матчится по URL;
  последний элемент `try_files` вида `@fallback` делает внутренний переход на
  него. Имя состоит из `@`, букв, цифр, `_`, `-` и `.`.
- `internal = true` скрывает обычный маршрут от прямых запросов: снаружи он
  отвечает `404`, а после внутреннего перехода доступен. Именованные location
  всегда внутренние. Цепочка переходов ограничена 10 шагами.
- `fastcgi_multiplex = true` разрешает несколько одновременных запросов в
  одном FastCGI-соединении по разным request id. Сервер должен поддерживать
  `FCGI_MPXS_CONNS`. В этом режиме тело запроса и ответ буферизуются; число
  соединений берётся из `fastcgi_pool_idle` (по умолчанию 4), до 16 запросов
  на соединение.
- `scgi_pass` отправляет запрос SCGI-приложению. Параметры собираются как для
  CGI (`REQUEST_METHOD`, `REQUEST_URI`, `QUERY_STRING`, `CONTENT_LENGTH`,
  `HTTP_*`), плюс `scgi_param`; при заданном `scgi_root` добавляется
  `DOCUMENT_ROOT`. Ответ читается как CGI: заголовки `Status`/`Content-Type`
  и тело. Соединение одно на запрос, тело ответа ограничено
  `max_response_bytes`.
- `uwsgi_pass` отправляет запрос uWSGI-приложению: четырёхбайтовый заголовок
  с `modifier1`/`modifier2`, length-prefixed переменные окружения и тело.
  Параметры те же, что у SCGI, плюс `uwsgi_param`. Ответ читается как
  CGI-заголовки с телом; поддерживаются `Content-Length`, chunked и закрытие
  соединения. `uwsgi_modifier1` и `uwsgi_modifier2` задают байты заголовка.
- `ajp_pass` отправляет запрос в Tomcat по AJP13: ForwardRequest, первая
  порция тела сразу, остальное — по GET_BODY_CHUNK. Ответ собирается из
  Send Headers / Send Body Chunk / End Response. `ajp_secret` передаётся
  атрибутом `secret`, если он задан. Соединение не переиспользуется.
- `auth_request = "/auth"` делает внутренний GET-подзапрос с заголовками
  исходного запроса. `2xx` разрешает запрос, `401`/`403` передаются клиенту
  вместе с `WWW-Authenticate`, остальные статусы превращаются в `500`.
  Целевой маршрут обычно помечают `internal = true`; подзапросы не кэшируются
  и не пишутся в access log отдельно.
- `satisfy = "any"` разрешает запрос, если прошла хотя бы одна проверка
  доступа: `ip_allow`/`ip_deny`, `auth_file` или `auth_request`. По умолчанию
  `all` требует все настроенные проверки. `client_auth`, лимит тела и
  rate-limit выполняются всегда и в `satisfy` не входят.
- `secure_link = { secret, md5, expires }` проверяет подпись ссылки. В
  query-форме `md5` и `expires` — шаблоны (`$arg_md5`, `$arg_expires`),
  ожидаемая подпись — `md5(expires + uri + secret)` в base64url без padding
  или hex. Просроченная ссылка даёт `410`, неверная — `403`. Без `md5` и
  `expires` работает path-форма: первый сегмент пути содержит
  `md5(secret + остаток пути)`.
- `X-Accel-Redirect` от upstream выполняет внутренний GET на указанный URI;
  ответ upstream отбрасывается, новый запрос проходит обычную маршрутизацию и
  `internal`-гейт. `X-Sendfile` отдаёт файл, только если он лежит под
  `x_sendfile_root`; абсолютный путь вне корня даёт `403`.
- `alias` работает как `root`, но сначала отрезает литеральный `path` маршрута:
  `path = "/static"` и `alias = "/srv/assets"` отдают
  `/static/app.js` из `/srv/assets/app.js`. `alias` требует `path` и не
  сочетается с `root`.
- `expires_secs` добавляет к статике `Cache-Control: public, max-age=N` и
  `Expires`. `etag = false` убирает `ETag` и проверку `If-None-Match`, оставляя
  `Last-Modified`. `if_modified_since = false` отключает проверку
  `If-Modified-Since` и всегда отдаёт тело. Эти поля не используются
  sendfile-быстрым путём — такие ответы идут через hyper.
- `index` — имена файлов, а не пути: элемент не может быть пустым, содержать
  `/` или `..`. Для каталога файлы перебираются по порядку. Запрос каталога
  без завершающего `/` получает `301`.
- `spa = true` отдаёт первый файл из `index` для путей, которых нет на диске.
  Если `index = []`, комбинация отклоняется.
- `index` и `spa` имеют смысл только вместе с `root`.
- Статика обслуживает только `GET` и `HEAD`, остальные методы получают `405`.
  Выход за пределы `root` через `..` и симлинки запрещён.
- `Range` поддерживает один и несколько диапазонов. Несколько отдаются как
  `206` с `multipart/byteranges`; пересекающиеся и соседние склеиваются.
  Неудовлетворимые диапазоны игнорируются, а если не осталось ни одного —
  `416`. Больше 64 диапазонов отклоняется, чтобы один запрос не превращался в
  тысячи `seek`. Сжатие к `206` не применяется. `If-Range` учитывается: при
  несовпадении сильного `ETag` или `Last-Modified` отдаётся полный `200`.
- `auth_file` включает HTTP Basic: без верных данных — `401` и
  `WWW-Authenticate: Basic realm="elira"`. Пароли проверяются bcrypt.
- `ip_allow`/`ip_deny` сравнивают адрес peer'а (с учётом PROXY protocol).
  `ip_deny` проверяется первым. Отказ — `403`.
- `client_auth = true` требует проверенный клиентский сертификат на этом
  маршруте; без него — `403`. `client_cn` и `client_issuer_cn` дополнительно
  сверяют CN субъекта и издателя. Для этого листенер должен запрашивать
  сертификаты: `tls.client_auth = "optional"` (сертификат проверяется, если
  прислан) или `"required"`. При включённом HTTP/3 то же нужно и в
  `http3.client_auth`. Фильтры без `client_auth = true` отклоняются при
  загрузке.
- Маршруты с `auth_file` или ACL не используют zero-copy `sendfile`:
  проверка доступа должна пройти в общем пути.
- `timeout_secs` переопределяет общий таймаут для запросов этого маршрута.
  Ноль отклоняется при загрузке. Истёкший таймаут — `504`.
- `requests_per_second`/`burst` создают отдельный limiter на маршрут; отказ —
  `429`. `max_body_bytes` проверяет `Content-Length` до обращения к upstream и
  фактический поток тела во время передачи; превышение даёт `413`.
- `rate_key` выбирает, что считает одним клиентом: адрес peer'а (`ip`,
  по умолчанию), полный `Authorization`, значение заголовка
  (`header:X-Api-Key`), cookie (`cookie:session`) или путь с query (`uri`).
  Без выбранного заголовка или cookie запрос попадает в bucket IP, поэтому
  лимит нельзя обойти их отсутствием. Ключи хешируются случайным ключом
  процесса и не хранятся в исходном виде. `rate_key` требует
  `requests_per_second` на том же маршруте.
- `max_concurrent` для проксирующего маршрута ограничивает число
  одновременных запросов к upstream. Permit удерживается до конца тела ответа,
  а при заполнении клиент получает `503` с `Retry-After: 1`. Для FastCGI/CGI и
  модулей значение по умолчанию — 16; для прокси лимит выключен, пока не задан.
- `error_pages` подменяет тело ответа с указанным статусом файлом. Статус
  сохраняется, даже если файл существует; `"404 =200 /404.html"` отдаёт файл
  со статусом `200`. `error_root` нужен, когда маршрут проксирует, а не отдаёт
  статику. Страницы применяются и к локальным отказам маршрута (`401`, `403`,
  `429`, `413`), а для остальных статусов используется глобальный
  `error_pages`.
- `early_hints` отправляет `103 Early Hints` со значениями `Link` перед
  финальным ответом. Поддерживается только открытый HTTP/1.1 без `sendfile` и
  h2c: hyper не умеет серверные 1xx, поэтому подсказки пишутся в сокет
  напрямую. На TLS и HTTP/2/3 они не отправляются.
- `error_pages = ["404 @fallback"]` вызывает именованный маршрут с
  `name = "@fallback"`. Поддерживаются статические, `return` и `redirect`
  цели; проксирующая named-цель требует полного request pipeline и пока не
  поддерживается.

## Ограничения и поведение

Что делает `SIGHUP`:

| Что | Поведение |
| --- | --- |
| `upstreams`, `routes` | применяются сразу; следующий запрос видит новую таблицу |
| `limits.*` таймауты, `routes`, `upstreams` | применяются сразу |
| `log.format` | применяется сразу, включая открытые keep-alive соединения |
| `health.*` | применяется, затем один внеочередной цикл проверок |
| `connect.*` | применяется сразу |
| `tls.cert`, `tls.key` | перечитываются; новые соединения — с новым сертификатом |
| `http3.*` | слушатель перезапускается, живые QUIC-соединения рвутся |
| `listen` | не меняется, в лог пишется `listen address changes need a restart` |
| `limits.max_connections`, `max_headers`, `max_header_bytes` | не меняются, предупреждение в логе |
| `limits.idle_timeout_secs` | не меняется и предупреждения не даёт: значение захвачено при старте |
| `metrics.listen`, наличие `[metrics]` | не меняются, предупреждение в логе |
| невалидный файл | reload отменяется, работает старый конфиг, в лог — ошибка |

Отдельно:

- `SIGHUP` перечитывает и TLS-материал, и h3-материал. Битый TLS-файл отменяет
  весь reload: старый конфиг продолжает работать. Битый h3-файл не мешает
  применить остальной конфиг, но h3-листенер после перезапуска не поднимется,
  и в лог уйдёт `http/3 listener stopped`.
- Добавление `[tls]`/удаление `[tls]` по reload технически меняет режим новых
  соединений на том же порту. На практике это не переключение «HTTP → HTTPS», а
  смена ожидаемого протокола на уже слушающем сокете: старые соединения
  доживают, новые должны угадать новый режим. Меняйте это рестартом.
- Соединения при остановке (SIGINT/SIGTERM) получают до 10 с на дозавершение
  запросов, затем до 5 с на graceful shutdown каждого соединения; после этого
  процесс выходит.
- `SIGUSR2` делает hot restart: запускает новый процесс того же бинарника и
  завершает текущий. Нужен `reuse_port = true`, иначе сигнал игнорируется.
  Новый процесс сразу биндит те же порты через `SO_REUSEPORT`; старый
  доживает 750 мс и уходит в обычный drain. HTTP/3-сокет также создаётся с
  `SO_REUSEPORT`.
- На не-Unix платформах reload и hot restart недоступны.

## Полный пример

Статика и прокси, TLS на TCP, HTTP/3 на UDP, health-проверки и метрики:

```toml
listen = "0.0.0.0:443"
proxy_protocol = true   # only when the port is reachable solely through the LB

[limits]
max_headers = 64
max_header_bytes = 16384
upstream_timeout_secs = 30
upstream_connect_timeout_secs = 5
upstream_send_timeout_secs = 30
max_connections = 4096
idle_timeout_secs = 60
max_body_bytes = 8388608
requests_per_second = 100
burst = 200
trusted_proxies = ["10.0.0.0/8", "192.168.0.0/16"]

[compression]
enabled = true
min_bytes = 1024

[tls]
cert = "/etc/elira/fullchain.pem"
key = "/etc/elira/privkey.pem"

[http3]
listen = "0.0.0.0:443"
cert = "/etc/elira/fullchain.pem"
key = "/etc/elira/privkey.pem"

[log]
format = "json"

[health]
enabled = true
path = "/health"
interval_secs = 5
timeout_secs = 2

[connect]
enabled = false

[metrics]
listen = "127.0.0.1:9090"

[[upstreams]]
name = "app"
servers = ["127.0.0.1:3000", "127.0.0.1:3001"]
balance = "least_conn"
retries = 1

[[upstreams]]
name = "api"
servers = ["10.0.0.11:8080", "10.0.0.12:8080"]

[[routes]]
host = "*"
upstream = "app"

[[routes]]
host = "api.example.com"
upstream = "api"

[[routes]]
host = "static.example.com"
root = "/srv/www"
index = ["index.html"]
spa = false

[[routes]]
host = "spa.example.com"
root = "/srv/spa"
index = ["index.html"]
spa = true
```

Порты TCP и UDP могут совпадать (`443` в примере) — это разные сокеты.
Проверить файл перед запуском:

```
elira check --config elira.toml
```

## Частые ошибки

| Сообщение / симптом | Причина | Что делать |
| --- | --- | --- |
| `limits.max_header_bytes must be at least 8192` | буфер меньше 8192 | поднимите до 8192 или выше |
| `limits.max_headers must be greater than zero` | `max_headers = 0` | уберите ноль |
| `limits.max_connections must be greater than zero` | `max_connections = 0` | уберите ноль |
| `limits.trusted_proxies: "..." is not a CIDR block` | строка не парсится как сеть | формат `10.0.0.0/8` или `127.0.0.1/32` |
| `route N needs exactly one of \`upstream\` or \`root\`` | у маршрута нет цели | добавьте `upstream` или `root` |
| `route N has both \`upstream\` and \`root\`` | указаны обе цели | оставьте одну |
| `route N: index file "..." must be a plain file name` | `/` или `..` в `index` | пишите `index.html`, а не путь |
| `route N: \`spa\` needs at least one index file` | `spa = true` при `index = []` | оставьте хотя бы один файл |
| `connect.enabled requires a non-empty connect.allow list` | включили `CONNECT` без целей | перечислите точные `host:port` |
| `connect target "..." is not host:port` | нет порта, есть `@` или `/` | формат `host:port` |
| `upstream "..." has no servers` | пустой `servers` | добавьте адрес |
| `upstream "..." has N retries, the maximum is 5` | слишком много повторов | уменьшите до 5 |
| `upstream "...": "..." is not host:port` | адрес без порта | `127.0.0.1:3000` |
| `upstream "..." is defined twice` | повтор `name` | переименуйте |
| `route for host "..." is defined twice` | повтор `host` | объедините маршруты |
| `only one \`host = "*"\` route is allowed` | два default-маршрута | оставьте один `*` |
| `route N points to unknown upstream` | опечатка в имени | сверьте с `[[upstreams]].name` |
| `no routes configured` | нет `[[routes]]` | добавьте хотя бы один |
| `unknown field \`...\`` | опечатка в имени поля | проверьте имя по этому документу |
| `unknown log format "..." ...` | не `text` и не `json` | исправьте значение |
| `invalid socket address` / ошибка TOML на `listen` | имя хоста вместо IP | `127.0.0.1:8080`, `[::1]:8080` |
| `tls.cert is required...` / `tls.key is required...` | пустое поле в `[tls]` | укажите непустой путь |
| `tls.client_ca is required...` | `client_auth` включён без CA | добавьте `client_ca` или верните `off` |
| `http3.client_ca is required...` | `http3.client_auth` включён без CA | добавьте `http3.client_ca` |
| `client_crl needs client_auth...` | CRL без mTLS | включите `client_auth` |
| `no CRLs in ...` | пустой CRL-файл | положите хотя бы один CRL |
| `acme HTTP-01 needs a listener on port 80 or acme.http01_listen` | HTTP-01 без порта 80 | задайте `http01_listen` |
| `cache.dir must not be empty` | пустой путь кэша | уберите поле или задайте каталог |
| `tls certificate name "..." is used twice` | одно имя в двух сертификатах | оставьте одно |
| `route N: "..." is not "STATUS /path"` | битая `error_pages` | формат `404 /404.html` |
| `"..." is not "STATUS /path"` | битый глобальный `error_pages` | формат `404 /404.html` |
| `global error_pages need error_root` | страницы без каталога | добавьте `error_root` |
| `log.sample must be a fraction between 0 and 1` | сэмплирование вне диапазона | задайте `0.0`..`1.0` |
| `route N: client_auth needs tls.client_auth...` | маршрут требует сертификат без TLS-проверки | включите `tls.client_auth` |
| `route N: client_cn/client_issuer_cn need client_auth = true` | фильтр без требования сертификата | добавьте `client_auth = true` |
| `route N: rate_key needs requests_per_second` | ключ без собственного лимита | задайте `requests_per_second` |
| `route N: "..." is not a rate key` | неизвестный ключ | `ip`, `authorization`, `header:NAME`, `cookie:NAME` |
| `tls.cipher_suites must not be empty` | пустой список политики | уберите поле или перечислите suites |
| `unknown cipher suite "..."` | опечатка в имени suite | сверьтесь с именами rustls |
| `unknown key exchange group "..."` | опечатка в имени curve | `X25519`, `secp256r1`, ... |
| `QUIC requires TLS 1.3 cipher suites` | TLS 1.2 suite в `[http3]` | оставьте только `TLS13_*` |
| `request headers cannot override hop-by-hop...` | `Connection`/`Transfer-Encoding` в request-заголовках | уберите framing-заголовки |
| `eject_secs must be greater than zero...` | эвикция без cooldown | задайте `eject_secs` |
| `hash_key needs balance = "hash"` | ключ без hash-балансировки | добавьте `balance = "hash"` |
| `"..." is not a hash key` | неизвестный ключ | `ip`, `authorization`, `header:NAME`, `cookie:NAME`, `uri` |
| `unix_tls needs listen_unix` | TLS на сокете без сокета | задайте `listen_unix` |
| `unix_tls needs a [tls] section...` | Unix TLS без сертификата | добавьте `[tls]` |
| `listen_unix_mode/listen_unix_owner need listen_unix` | права без сокета | задайте `listen_unix` |
| `listen_unix_owner must look like...` | имя вместо uid:gid | используйте числа |
| `weights must contain one positive value per server` | длина не совпала | выровняйте `weights` и `servers` |
| `weights and balance = "hash" cannot be combined` | веса с hash | уберите `weights` |
| `"..." is not a retry condition` | мусор в `retry_on` | `error`, `timeout` или 5xx |
| `route N: timeout_secs must be greater than zero` | нулевой таймаут | уберите поле или поставьте больше нуля |
| `http3.cert must not be empty` | `[http3]` без сертификата | задайте `cert` и `key` |
| `health.path must start with '/'...` | путь без `/` | `/health` |
| `health.interval_secs must be greater than zero` | ноль при `enabled = true` | поставьте `5` или больше |
